## Context

上一轮我把台账的「单据编号」做成了**文本层面去重**：同一单据只在首行显示编号，其余行列显示「〃」。这不是你要的合并。你要的是**方案二：按单据折叠成一行**，并且**用一个独立按钮开关**（关掉就回到现在的逐行明细）。

现状（`src/screens/LedgerScreen.tsx`）：台账是服务端分页（每页 100 行，`fetchPage`），行顺序按 `doc_date, id`；`rows` 直接铺进 react-aria `Table`，超 60 行走 `useVirtualRows` 窗口切片。react-aria 的 `Cell` 不支持 `rowSpan`，所以要做「合并成一行」只能在前端把同一单据的行折叠成一条聚合记录再渲染，而不是控制 `<td rowspan>`。

## 方案

### 1. 去掉上一轮的错误实现
- 删掉 `LedgerScreen.tsx:144` 的 `mergedDocNo` useMemo，以及 `513-515` 里渲染「〃」的写法，恢复为 `{row.docNo ?? "—"}`。

### 2. 新增「按单据合并」开关按钮
- 位置：筛选条尾部（「清除筛选」旁边），BoardUI `Button`，`variant` 在开启时用 `secondary`，图标用 `@remixicon/react` 的 `RiMergeCellsHorizontal`（若不存在则用 `RiTableLine`）。
- 状态存 `useState`，并用 localStorage 记住（key `ledger.mergeByDoc`，沿用 `src/lib/printPrefs.ts` 里已有的存储 + 事件通知写法，不引入新依赖）。只读站（`!isTauri`）也显示该按钮——纯展示开关，不需要写权限。

### 3. 合并算法（前端，纯函数）
新增 `src/lib/mergeDocs.ts`：
```ts
export interface MergedRow { /* 与 LedgerRow 同形，但 itemName/qty/price 等是聚合值 */ }
mergeRowsByDoc(rows: LedgerRow[], merged: boolean): (LedgerRow & { groupCount: number })[]
```
规则：
- 不合并时原样返回。
- 合并时按 `kind|docNo` 把**相邻**行折叠成一条；`docNo` 为空的行各自独立成行（不合并）。
- 聚合字段：`itemName` = 各行物料名用 `、` 连接（超过 3 个显示前 3 个 + ` 等 N 项`），`itemCode` / `unit` / `priceMicros` 显示为 `—`，`qty` 求和，`amountCents` 求和，`remark` / `partner` / `owner` 取首行，`flags` 取并集，额外带 `groupCount`（该单据行数）。
- 用 `useMemo` 包住。
- 合并只作用于**当前页**（服务端分页不变），跨页的同单据不会合并——这点会写进按钮的 tooltip 说明。

### 4. 表格渲染
- 表头在合并模式下把「单据编号」列加宽一点，「物料名称」列标注为聚合列；`Table` 总列数保持 13 不变。
- 行渲染：`key` 用合并组首行 id；勾选框在合并模式下**禁用**（批量改/删按整单做语义不对，先不开放），显示 `groupCount` 个行的小徽标在物料名称后面，例如 `外卡 φ10、轴承 6204 等 3 项`。
- 单击合并行打开该组首行的详情抽屉（保持现有 `openDetail` 行为）。
- 合并模式下关闭虚拟滚动（合并后行数通常远小于 60，切片反而会切断聚合逻辑；用 `merged ? rows : slice` 即可）。

### 5. 合计条与分页文案
- 合计条不受影响（走服务端 `totals`）。
- 底部文案在合并模式下改为 `第 1–N 条（合并自 M 行），共 X 条`。
