# 仓库出入库明细

Tauri 2 + Rust + React 19 + Vite 7 + Tailwind v4 + BoardUI 的仓库台账程序。
本机打开即管理员：导入 Excel、改行、删除、导出都在这台电脑上做；
同一程序的 80 端口对局域网开放一份**只读**台账，同事用浏览器就能查、筛、导 CSV。

## 它解决什么

一张 `仓库出入库明细_5611_Modified.xlsm` 里，入库明细 5,887 行、出库明细 1,790 行，
按日期、供应商、归属、物料散在两张表里。程序把这两张表读进本地 SQLite：

- 台账页：一份可筛、可分页、能导出的明细，入库/出库用不同的类型标记
- 汇总页：入库金额、出库金额、净入库、按月柱状图、按归属/供应商排行
- 导入页：换一个 Excel 文件时，先看表头对照结果，再预览校验，最后落库
- 只读站页：开关 80 端口、给同事发地址、看访问记录

## 运行

前置：Node ≥ 20、Rust 1.90（`rust-toolchain.toml` 已钉版本）、MSVC。

Windows 需要「Visual Studio Build Tools」的 **Desktop development with C++** 工作负载：
`scripts\rust90.cmd` / `scripts\bundle.cmd` 先用 `vswhere.exe` 自动找 `vcvars64.bat`，
找不到时再读环境变量 `VCVARS`；都没有就打印安装提示并退出，不会去猜某个盘符。
Git for Windows 自带的 `usr\bin\link.exe` 会盖掉 MSVC 的链接器，两个脚本会在调用
`cargo` 前把 PATH 里所有 `*/Git/usr/bin` 条目剔掉。

```bash
npm install
npm run tauri dev          # 开发：前端 5173，桌面窗口自动打开
```

开发时如果仓库根目录有 `.xlsm` / `.xlsx`，首次启动（库为空）会自动导入一次，
并在界面右上角提示导入结果。之后要换数据去「导入」页。

## 主题与字号

侧栏底部有「浅色 / 深色」切换，两套都用 BoardUI 的语义 token，切的是 `<html>` 上的 `.dark`：

- 选择存在 `localStorage` 的 `ledger.theme`，重开程序保持
- `public/init.js` 首帧外链脚本先读存储再上色与定字号（兼容 `script-src 'self'` CSP），不会先闪一下深色
- 桌面端会同步 Tauri 窗口主题，标题栏跟着变
- 只读站是同一套前端，局域网同事也能各自切自己的
- 默认深色；从未选过时不读系统主题

侧栏底部的**字号**控件把界面整体缩放，四档：小 / 标准 / 大 / 特大（根字号 14 / 16 / 18 / 20px）：

- 只改 `<html>` 根字号，BoardUI 的字号 token 全是 rem，会整体等比缩放
- 存在 `localStorage` 的 `ledger.fontScale`，只影响本机显示，不写库、不影响只读站
- 表格里原本写死 px 的字号已换成 rem，跟着一起走
- 仓库现场屏幕远一点就用大号、特大号

## 导入规则

首行表头按内置别名对照（不区分首尾空白、忽略括号备注）：

| 标准字段 | 常见表头 |
|---|---|
| 日期 | 入库时间 / 日期 / 出库时间 |
| 单据编号 | 单据编号 / 入库单号 / 出库单号 |
| 送货单号 | 送货单号 / 验收单号 |
| 物料编码 | 物料编码 / 物料编号 / 图号 |
| 物料名称 | 物料名称 / 名称 / 品名 |
| 数量 / 单价 / 合计 | 数量 / 单价（进货单价）/ 合计（金额） |
| 供应商 / 采购人 | 供应商名称 / 采购人 |
| 归属 / 领用人 | 归属（使用部门、车间）/ 领用人 |

- 一张表要能同时对上「日期、数量、物料编码或物料名称」才会被当成明细表
- 表名带「入库」算入库，带「出库 / 领用」算出库；都没有则看有没有供应商/送货单号
- 日期支持 `2025/10/30`、`2025-6-30`、`2025年1月5日`、Excel 序列号（45759）
- 金额统一按分（整数）入库，显示时除以 100
- 认不出的行不丢：能填的先填，打上提醒（无编码 / 无单价 / 无金额 / 数量缺失 / 数量×单价≠合计）
- 写库是一个事务：要么整批进，要么一条不进
- 导入历史可整批删除；重导同一份文件会提示（按文件哈希）

### 图号页

基础资料页有「图号」标签（在物料、供应商之间），管理 `items.drawing_no`：

- **有图号**：列出已填图号的物料，可按图号/编码/名称搜
- **缺图号**：列出**加工件里还没填图号**的，就是待补清单
- 每行可直接改图号，保存只更新这一个字段

图号不单独建表：它和物料是一对一，存在 `items` 上避免两处维护。
当前数据：224 条有图号，23 条加工件待补（源表里 `YW-01`… 这批本来就没填）。

### 「基础信息」表的合并

工作簿的「基础信息」表（934 行）是旧的物料单价表，与「物料编号」重叠仅 333，
另有 **558 个名称只在基础信息里**，其中 127 个台账里实际在用。

这张表的布局有两处反直觉，导入时必须按下面的规则读：

| 列 | 表头 | 实际内容 |
|---|---|---|
| B | 图号 | **外购件的物料名称**（如「外卡（轴）φ8」） |
| C | 名称 | 只有 241 行有值，**全是加工件**（B 列才是图号） |
| F | 类型1 | 外购件 / 加工件 |

所以取值规则是：**名称取 C，C 为空回退 B；图号只在 C 有值时另存**。
按这个规则导入后：外购件 631、加工件 244，台账物料名称覆盖率 99%。

导入时 sheet 会先处理带「物料编号」的表，再处理「基础信息」，
这样旧表能按名称给已有物料**回填类型与图号**，而不是造出重复行。

## 金额与单价精度

这两者精度不同，代码里不可混用：

| 字段 | 单位 | 说明 |
|---|---|---|
| `amount_cents` | 分（1e-2 元） | 合计金额。源表合计本身就是分精度 |
| `price_micros` | 万分之一元（1e-4 元） | 单价。源表里 4,920 行是厘/丝级 |

为什么单价要 4 位小数：源表里大量螺丝弹垫的单价是 `0.0032`、`0.0044`，
按「分」存会被截断成 `0.00`，导致「数量 × 单价」重算与合计差出约 ¥4,784。
改成万分之一元后，5,639 行单价与源表逐行一致，偏差 0 行。

换算入口固定为三个，不要直接乘除：

- Rust：`import::to_cents`（金额）、`import::to_micros`（单价）、`voucher::line_amount_cents`（数量×单价→分）
- 前端：`format::priceText`（显示）、`format::priceInput`（编辑框初值）、`format::parsePriceToMicros`（输入解析）

### 单据查询

开单页右上角的「单据查询」，按编号查历史单据，**两种来源一起查**：

- 完整编号精确命中（`20260831206`）
- 只填片段也行（`0831` 找出当天所有单）
- 本机开的单标可编辑，点开载入编辑器继续改
- Excel 导入的单标「导入」，点开是只读明细，带源表行号与数据提醒

## 打印

开单页保存成功后自动弹出 **A4 打印视图**（`.print-overlay` 里的 `.print-paper`），保存失败不打印：

- 按单据实际行数出稿：有几行打几行，不补空行；超过上限才分页
- 「设置」页可调每页行数上限（默认 18 行，1–40），存 `localStorage` 的 `ledger.print.rows`，只影响本机排版
- 常用 5~10 行的单据永远一页一张，不会有大片空白
- 打印视图与打印偏好都只在本机，不进数据库、不同步到只读站

## 基础资料（物料、供应商与字典）

「基础资料」页维护三块内容，开单时直接引用：

- **物料**：编码、名称、类别、单位、参考单价、默认供应商、在用/停用
- **供应商**：名称、联系人、电话、备注，并显示它在台账里出现过多少行
- **字典**：单位 / 类别 / 类型 / 出库部门 / 采购人 五类文字字段的统一候选

数据来源两条，都是幂等的：

1. **从工作簿导入**：读「物料编号」「供应商名称」两张表。按表头认列，不依赖 sheet 顺序；已有编码只更新名称/单位/单价等字典字段，不覆盖手填的备注。
2. **从台账补齐**：把台账里出现过但主数据缺的物料和供应商补进去（首次启动自动跑一次）。

实测导入结果：物料 **3,856** 条（8 个类别，原材料 1,318 / 五金类 727 / 电器类 650 / 螺丝标准件 351 / 轴承类 255 / 气动类 193 / 其他类 186 / 电机类 79），供应商 **162** 家。

开单时的联动：

- 填物料编码 → 带出名称、单位、参考单价（出库不带单价）
- 供应商是带下拉的输入框，可以选也可以直接打字

### 字典（单位 / 类别 / 类型 / 出库部门 / 采购人）

这五类原来都是自由文本：同一个部门在台账里写成「470FQ/1台」和「470FQ/一台」，
统计时就被拆成两组；单位下拉每次现查历史值，慢且不完整。现在统一收在 `dict` 表
（迁移 `009_dict.sql`），首次升级时从 `items` 与 `ledger` 里灌好初值：

| 类别 | kind | 来源列 | 初值规模 |
| --- | --- | --- | --- |
| 单位 | `unit` | `items.unit` | 37 条（个 1788 / 只 777 / 件 434 …；`0` 是粘贴残留，不收） |
| 类别 | `category` | `items.category` | 9 条（原材料、五金类、电器类 …） |
| 类型 | `item_type` | `items.item_type` | 2 条（外购件 / 加工件） |
| 出库部门 | `owner` | `ledger.owner`（台账里叫「归属」） | 17 条（乾力车间 476 / MQ 193 …） |
| 采购人 | `buyer` | `ledger.buyer` | 3 条（严兰兰 / 周梓棋 / 测试） |

行为约定：

- **改名同步数据**：在字典里把「470FQ/一台」改成「470FQ/1台」，会同时改写台账与物料里用到旧值的行，返回受影响行数，界面提示「同步改了 N 行数据」。
- **还在用就不能删**：删除前先数引用行数，有引用直接拒绝并提示先停用或改名；没有引用的才允许删。
- **停用只影响下拉**：停用项不再出现在开单候选里，历史数据原样保留。
- **录入即登记**：开单时手输的新单位/部门/采购人会在保存时写进字典（`hits` 累加），导入 Excel 的明细同样登记。
- **从数据补齐**：手工改过专有名词之后点一次，把现有数据里还没进字典的值收进来。

开单页取字典的位置：明细的「单位」列是带搜索的下拉（可现输），表头的「出库部门」和
「采购人」也是。物料表单的「单位」「类型」候选同样来自字典。

## 多仓库

侧栏顶部是仓库切换器，当前仓库名下面标着它的台账行数；点「管理仓库…」可以新建、编辑
（改名、备注、打印抬头）、停用和删除（只在桌面端提供）。

- **业务数据按仓隔离**：`ledger` / `vouchers` / `imports` 三张表带 `warehouse_id`。
  台账、库存、开单、导入、导出、清空都只作用于当前仓库。
- **基础资料全库通用**：物料、供应商、字典（单位/类别/类型/出库部门/采购人）不分仓，
  多个仓共用同一套档案，删仓库也不会连带删物料。
- **打印抬头按仓配置**：`warehouses.company_name`，不同仓库可以印不同的公司名。
  可写多行（公司名 + 地址/电话，最多 3 行、每行 60 字），开单页单头与 A4 打印都用它；
  留空则纸面不印公司名。升级后「主仓库」沿用原来的「温州乾力机械有限公司」。
- **单号每仓独立**：仍是 `YYYYMMDD` + 3 位流水，唯一索引改成 `(warehouse_id, kind, doc_no)`，
  两个仓同一天可以各有一张 `20260901001`。
- **汇总页可以看全部**：汇总页的「全部仓库」开关把 `warehouse_id` 置空做合并统计，
  只用于看总量；台账、库存、CSV 导出始终严格单仓。
- **只读站的仓库选择是本地的**：每个同事在自己浏览器里选仓库，存在 `localStorage`，
  互不影响；`/api/warehouses` 只返回清单，`/api/summary*` 才接受 `warehouse=all`。
- **开单草稿按仓各存一份**：`ledger.voucher.draft.<warehouseId>`，切回来接着录；
  老版本那份不带的草稿会在首次升级时归到当前仓。
- **删除仓库需要二次确认**：有数据时后端先报数量，确认后在一个事务里删掉该仓的
  台账、单据与导入记录；始终至少保留一个仓库。

升级到这一版时，老库里的全部数据会落到自动创建的「主仓库」，单号与日期区间不变。

## 开单与批量操作

**开单页**（侧栏「开单」）照 Excel 里那两张单子做：

- 入库单：供应商、送货单号、采购人、单据编号、入库时间 + 明细（物料编码/名称/单位/数量/单价/合计/备注）
- 出库单：归属、领用人、单据编号、出库时间 + 明细（出库没有单价，金额记 0）
- 单据编号沿用 `YYYYMMDD` + 3 位当日流水（`20260901001`），入库与出库各自独立编号
- 选物料编码会自动带出名称、单位和最近一次入库单价（从历史台账聚合，不另建主数据表）
- 开单产生的行 `sheet` 记为 `voucher:in` / `voucher:out`（退货单为 `voucher:ret`），`voucher_id` 串回单据头
- 删单据会连带删掉它的明细；明细在台账里被删空时，单据头也会自动清理

### 退货单（退回供应商）

- 方向是出库（库存减少、金额计入出库），但单独标记 `is_return`、单独取号 `TH` + `YYYYMMDD` + 3 位流水（`TH20260901001`）
- 两种开法：
  - 打开一张**入库单**点「退货」：带出未退明细，数量默认带满可退、单价沿用原单，保存时严格校验超退
  - 页头「新退货单」：手工开，可自己填原入库单号；适用于 Excel 导入的入库单（库里没有单据头，拿不到可退数量），不校验超退
- 单头记录原入库单 `source_doc_no` 用于追溯；来源单被删时退货单不会自动跟着删
- **严格不允许超退**（带来源单时）：本次数量 ≤ 原数量 − 已退数量（按物料聚合比较），超出直接拒绝保存；编辑退货单时先扣掉自身
- 开单记录与台账都有「退货」胶囊筛选；选「出库」**不包含**退货单，选「退货」只看退货单
- 汇总与库存口径不变：退货计入出库，不新增汇总卡片
- 纸面按「退货单」排版：带单价与金额，签字行第三格是「供应商签收」

**开单记录页**（侧栏「开单记录」）是完整历史：开单页底部只留最近 5 张做快捷回看。

- 服务端分页（`voucher_list_page`，每页 20/50/100/200 可存），按日期倒序
- 筛选：关键字（单号 / 送货单号 / 供应商 / 归属 / 采购人 / 明细物料编码或名称）、类型、日期区间、归属、采购人
- 底部「共 N 张 · 入库 X · 出库 Y · 合计 ¥…」按**整份筛选结果**统计，不是当前页
- 点一行看明细；详情里可 A4 打印、删除、「载入编辑」或「转单」——
  后两个动作会切回开单页并复用它的表单，「转单」把明细抄成反向类型的新单（原单不变）；
  入库单的详情里还有「退货」，按未退数量生成一张退货单；开单页有未保存内容时会先确认
- 只在桌面端出现：只读站（80 端口）导航里没有这一页

**台账批量操作**：表格支持多选，选中后出现批量操作栏。

- 批量改只作用于「归属 / 采购人 / 备注」——数量、单价、金额属于记账数据，必须逐行核对，不提供批量改
- 批量删走同一套确认流程，单次上限 5000 行
- 只读站里既没有开单页也没有多选，写操作只在桌面端

## 只读站的边界

这是硬边界，不靠前端隐藏按钮：

- 路由表只有 `GET`；`POST/PUT/PATCH/DELETE` 一律 405；未注册的 `/api/*` 返回 JSON 404
- 只接受回环与私网来源，公网地址直接 403；不信任 `X-Forwarded-For`
- 每 IP 令牌桶 30 次/秒，超出 429；导出上限 20 万行
- `X-Frame-Options: DENY`、`Content-Security-Policy`、`X-Content-Type-Options: nosniff`
- 80 端口被占用时自动退到 8080，并在只读站页显示原因
- 访问记录只保留最近 500 条

写数据的命令（`ledger_update`、`import_run`、`import_delete`、`web_start/stop`）只通过
Tauri IPC 暴露，浏览器里调用不到。

## 开发命令

```bash
npm run typecheck                  # tsc --noEmit
npm run lint                       # eslint（只看 src/，BoardUI 源码不参与）
npm run format                     # prettier 写回 src/**/*.{ts,tsx}
npm test                           # vitest 单测（纯函数与 localStorage 读写）
npm run build                      # 桌面端产物 dist/
npm run build:remote               # 只读站产物 dist-remote/
scripts\rust90.cmd test --lib      # Rust 单测（自动切入 src-tauri）
scripts\rust90.cmd fmt --check     # rustfmt 检查（rustfmt.toml）
scripts\rust90.cmd clippy --lib --tests -- -D warnings
scripts\bundle.cmd                 # 打包 NSIS 安装包
```

推送或开 PR 时 GitHub Actions 会跑同一套检查（`.github/workflows/ci.yml`），
前端与后端是两个独立 job，可以并行看结果。

`scripts/verify-*.mjs`（`verify-db-state.mjs` / `verify-voucher-db.mjs`）用于针对本地 SQLite 数据做落库复核，不参与生产构建。

## 已知取舍

- 出库明细没有单价/合计列，所以出库金额为 0；汇总页会自动把主口径切到入库，
  并在图表注释里写明「出库没有金额」。退货单是例外：它带单价与金额，也计入出库金额。
- 只读站与桌面窗口读同一个 `ledger.db`，写入只发生在桌面端。
- 修改与删除是直接写库，不保留行级历史；需要追溯时用导入批次的 `row_no` 回原表核对。
